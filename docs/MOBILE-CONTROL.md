# 手机遥控（局域网）

用手机浏览器指挥运行在电脑上的 PlaitCode：发需求、回答追问、看进度、批准工具授权。

暂定只做**同一 WiFi**（局域网直连）。跨网络为什么不能直接连、以后怎么走，见文末。

---

## 1. 怎么用

1. 电脑上打开命令面板 → `PlaitCode: 手机遥控（扫码）`；
2. 窗口里有二维码和 6 位数字；
3. 手机连**同一个 WiFi**，扫码（或打开窗口里那个地址手输 6 位数字）；
4. 进去就是团队群，可以说话、看进度、点授权。

也可以从设置页「协作 → 手机遥控」进入，或点状态栏的「手机遥控已开」。

**不需要**：装 App、注册账号、登录 GitHub、把电脑暴露到公网。
**需要**：手机和电脑在同一个局域网，且这个 WiFi 没有开启「AP 隔离」（很多公司/酒店 WiFi 会禁止设备互访，表现是页面打不开）。

## 2. 手机端能做什么

手机页和电脑上的「团队群」窗口**是同一套语义**（同一份 `mobileState()` / 同一个 `sendGroupMessage()`），
差别只在排版：手机是单列，操作条放在列尾。

| 能 | 不能 |
|---|---|
| 以甲方身份发需求（频道内设备都会收到） | 改权限预设、换模型、动设置 |
| **由谁执行**：底部 chip 选收件设备（默认「所有人」），选中的设备掉线自动退回所有人 | 看工具日志、命令输出、代码 diff（那是电脑上主对话的事） |
| 回答乙方的追问（自动并入同一条需求，不会另开一条） | 在没有电脑开着的情况下干活（agent 仍在电脑上跑） |
| **停止执行**：按钮等同电脑光标那颗，广播到群里所有设备一起停 | — |
| 看谁说了什么、做到哪一步；顶部显示当前项目 | 发图片 / 语音（目前只有电脑端支持） |
| **已读回执**：每条下面显示谁读过；你的消息没被读时点名在等谁 | 看队友之间的往来消息（`dialogue` 只在电脑端展示） |
| 批准 / 拒绝工具授权（可关闭） | — |

## 3. 为什么安全边界是这样

手机能批准授权，等于**拿到这台电脑的遥控器**。所以：

| 关卡 | 作用 |
|---|---|
| 6 位码，一次有效 | 拍下屏幕也没用，换完即作废 |
| 连错 5 次锁 5 分钟 | 穷举一百万种组合要好几年 |
| 会话 12 小时 | 一天一换，不用每次输码 |
| `HttpOnly` + `SameSite=Strict` | 页面脚本偷不走；别的网站借你的浏览器发不出请求 |
| `x-plaitcode-mobile: 1` 自定义头 | 跨站表单设置不了自定义头，CSRF 走不通 |
| 授权卡 3 分钟过期即拒绝 | 不会把工具线程永远挂住 |
| 手机批准可一键关闭 | 只让手机「看和说」，授权留在电脑上 |

**局域网是明文 HTTP。** 这意味同一 WiFi 下有抓包能力的人能看到内容（包括验证码）。
这也是为什么只绑局域网、并且默认不暴露到公网。任何跨网络方案都必须走 HTTPS。

## 3. 手机界面与消息顺序

界面按飞书 / 微信的即时通讯习惯排：别人的消息左侧带头像与名字，自己的贴右；同一个人的连续几条合并成一组，
间隔超过 5 分钟插一条居中时间分隔（跨天写「昨天 / M月D日」）；阶段与用时收成气泡里的小标签；
追问与授权是卡片，底部是圆角输入框 + 圆形发送键。

**和电脑团队群对齐的信息**：顶部显示 `HWChat · 设备名`、连接状态、**项目名**、
「N 台设备：Windows · …、macOS · …」；每条气泡下面都有「已读：…」（自己的话滤掉「本机」只列别人，
没人读时点名「等待确认收到：…」）；agent 之间的往来（`dialogue`）也按时间线显示，
标「队友对话 / 回复队友」与 `@某人`。**界面上永远不出现设备 id** ——
主机在 `mobileState()` 里就把 id 翻成「系统 · 设备名」，另附 `labels` 表兜底。

**自适应**：高度用 `100dvh`（键盘 / 地址栏不会把输入条顶出屏幕），
窄屏 ≤380px 与宽屏 ≥600px 各一档字号与间距，气泡强制换行，没有横向滚动。

**发送**：`/m/send` 立刻返回 202，自己的话先画出来（「发送中…」），真正的发送在后台；
失败会作为一条群消息写回群里。以前 `await` 整个发送流程（可能包含打断正在跑的一轮），
界面就一直停在「发送中…」——手机上看就是「发不出去」。

**顺序只有一条规则：按本机到达顺序，甲方需求永远排在回应它的乙方发言之前。**

两个真会出错的地方（都已在 `sortGroupTimeline()` 里处理，手机页 / 电脑群窗口 / 群记录共用）：

| 现象 | 原因 |
|---|---|
| 回复显示在我刚发的消息上面 | 两台机器系统时钟不一致（实测 macOS 比 Windows 慢 123 ms），按两端时间戳排会颠倒 |
| 乙方「收到 / 开始执行」跑到我的需求上面 | 需求先在协议层到达、本机 agent 立刻回话，而需求气泡是发送方随后才广播过来的 |

自己刚发的那条会**立刻出现**（标「发送中…」），不等服务器回声 —— 否则等待期间看到的会是「乙方先回了」。

## 4. 消息怎么走（和电脑上是同一条管线）

```
手机浏览器
  │  POST /m/send   （会话 Cookie + 自定义头）
  ▼
LanSyncService（电脑，HTTP 监听）
  │  bridge.onMobileMessage(text)
  ▼
ChatPanel.sendGroupMessage(text)   ← 和「团队群窗口」调用的是同一个函数
  │  ├─ 有未答追问 → 当「回答」并入同一需求
  │  └─ 没有追问   → 当「新需求」→ 广播给另一台设备 + 本机开跑
  ▼
团队群记录 / 对齐账本 / 主对话执行
```

**故意不在网络层另写一套判断。** 手机和电脑如果各自判断「这是回答还是新需求」，
迟早会得出不同结论，那是最难查的一类 bug。

手机端的四个写接口，一一对应电脑上的四个入口：

| 手机 | 电脑上的同一件事 |
|---|---|
| `POST /m/send` | 团队群窗口发消息（`sendGroupMessage`） |
| `POST /m/stop` | 团队群状态条上的「停止执行」（同一个 `broadcastStop()`） |
| `POST /m/approve` | webview 授权卡片 |
| `GET /m/state` | 同一次 `mobileState()` 快照（项目名、消息、账本、已读） |

授权是另一条路：

```
工具要跑命令 → ChatPanel.requestToolApproval()
  ├─ 电脑：webview 卡片 / 原生通知（危险档以前是模态框）
  └─ 手机：LanSyncService.awaitApproval() → 手机页面上的卡片
  两者 Promise.race()，谁先点谁算数；另一方自动撤卡
```

危险档（删库、`curl | sh`、解释器内联脚本）原本用模态框，是为了让 webview 无法自己批准自己；
**开着手机授权时改用非模态原生通知** —— 否则会出现「手机已经批了，模态框还挂在屏幕上」。

## 5. 跨网络：为什么不能「都登录 GitHub」就连上

GitHub 登录解决的是**身份**（你是谁），不是**通道**（怎么找到对方）。
手机在 4G 下，路由器后面的电脑没有公网地址，两个 NAT 后面的设备互相发不出包。

真正可行的三条路：

| 方案 | 原理 | 代价 |
|---|---|---|
| **Cloudflare Tunnel + Access** | 电脑主动外连，Cloudflare 给一个域名；Access 用 GitHub 当身份提供方 | 一个域名；无需自建服务端。**已选定方向** |
| 私有仓库 / Issues 当信箱 | 所有设备都能连 GitHub，往同一个文件或 issue 里「投递/取件」 | 免费；轮询延迟 3–5 秒；写入会产生 commit 噪音 |
| 自建中转（WebSocket） | 电脑保持长连接到中转，手机连中转 | 要租服务器、写鉴权、管证书与在线率 |

页面这一层已经为迁移准备好了：所有请求走**相对路径**、身份走 **Cookie**，
换到隧道后面只需要改访问地址，页面不用重写。

## 6. 排查

| 现象 | 原因 | 处理 |
|---|---|---|
| 手机打不开地址 | 不在同一 WiFi / WiFi 开了 AP 隔离 | 换手机热点再试 |
| 提示「验证码不对」 | 码过期（10 分钟）或已用过一次 | 电脑上点「换一张」 |
| 提示「试错太多次」 | 同一来源连错 5 次 | 等 5 分钟，或换一张码 |
| 输入后一直空白 | 电脑上手机遥控被关掉了 | 重新打开（状态栏 / 设置页） |
| 点「进入团队群」没反应 | 页面脚本里有一颗语法错误，整段脚本不执行（0.4.27 前的 `'\n'` 事故就是这个症状） | 升级到 0.4.27+；再遇到就用手机浏览器控制台看第一行红字 |
| 手机上不出现授权卡 | 关闭了「允许在手机上批准工具授权」 | 在手机遥控窗口打开它 |
| 端口被占用 | 和别的程序抢同一个端口 | 改 `plaitcode.lanSync.port` |
