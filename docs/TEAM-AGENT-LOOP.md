# 团队群 Agent 循环（VS Code 版 OpenClaw）

> 参考实现：[zhayujie/CowAgent](https://github.com/zhayujie/CowAgent)（Agent Harness）、
> [agentscope-ai/AgentTeams](https://github.com/agentscope-ai/AgentTeams)（Matrix 房间里的多 agent 协作）。
> 目标：**一个脑子**同时负责回话、追问、干活，而不是三条管道各管一段。

## 1. 为什么改

现状是「管道」：

```
群消息 → classifyGroupIntent（16 token） → 判 CHAT：无工具、无记忆、400 token 干答
                                        → 判 TASK：完整 agent 循环（有工具、能读代码）
```

同一条消息，能力差一个量级，而分流是一次 16-token 调用完成的。
用户实况：同一个问题，有时给出带行号的核对表，有时只能干答 —— **那不是同一个东西在回答**。

参考实现里没有这一刀：通道只负责收发，**Agent Core 自己决定**这句话该回、该问、还是该做。

## 2. 目标架构（对齐 CowAgent 的分层）

| CowAgent 层 | 本项目对应 |
|---|---|
| Channels | 团队群窗口 + 局域网/中继传输（`lanSync`） |
| Agent Core | 一次 agent 循环（现有 `AgentRunner`，带工具） |
| Memory | 磁盘上的对话历史（`storage`），群里的活固定一条会话 |
| Tools / Skills | 现有工具集 + 技能注册表 |
| Multi-Agent | 每台设备一个 agent，共享同一个群会话上下文 |

**消息流（新）**：

```
群消息（任意来源：本机输入 / 对端 / 手机）
   └─→ 落成一条需求（带 project / repo / assignee）
         └─→ 进同一条持久会话，跑一次 agent 循环
               agent 自己决定：
                 · 只是问 → 在群里简短回答（带依据）
                 · 不确定 → 群里追问
                 · 需要授权 → 群里申请，等甲方回「授权」
                 · 要改代码 → 拆清单、执行、群里报结果
```

## 3. 保留的确定性护栏（不靠模型）

这些是**代码保证**，不是提示词：

- **项目门禁**：任务所属项目与本机不同 → 先追问，不执行；
- **指派门禁**：`assignee` 不是本机 → 只记录不执行，并在群里说一句；
- **跑完回执**：一轮结束必发群消息（成功 `result` / 未完成 `progress`），模型没报也会补；
- **授权卡**：群里回「授权/拒绝」结算最近一张；
- **群会话唯一**：群里的活固定一条会话，不再每条新建（权限也不会被重置）；
- **对话轮换**：单条团队任务对话超 24 条消息 / 4 万 tokens 自动归档并写交接摘要
  （曾出现 Windows 那条堆到 544KB，每一步都要重读，mac 12 秒而 Windows 十分钟）；
- **群消息不被吞**：本机正在跑任务时，群里来的消息豁免 `pendingSends` 锁 ——
  忙就先停掉上一轮、只执行最新的，最少也要把消息发进群（以前是判忙发生在发群之前，直接丢）。

## 3.1 任务清单的硬规则（写进提示词）
「不达目标不罢休」的前提是清单本身可验收，否则 agent 会自己糊弄自己：

- 每条都是**能被验证的结果**（看得见的界面效果 / 某字段存在 / 某条命令通过），
  禁止「优化一下」「修一下」；
- 每条都必须是**这台机器自己能做完的**；
- **跨平台对齐只要求行为一致**（用户看到的效果一样），不要求逐字一致 ——
  两台代码库本来就不同（语言、框架、目录都不一样），字面一致永远做不到；
  禁止把「逐字一致 / 行数一致 / 文件内容相同 / 比对两份代码差异」写成任务项，
  也禁止为了对齐去读队友那台的仓库或服务器；各自在本机实现，再在群里用「用户能看到的效果」互相对一遍。

## 3.2 谁说这些话（0.10.3）

用户 2026-11-24：「我看到的是程序或者提示词设置好的程序，而不是 agent 的智能输出输入和互相对话沟通」。

- **正文只放 agent 自己写的话**：完成/没完成的回执不再拼「【项目 X】这台做完了…改动文件：a、b」，
  项目 / 用时 / 改动文件 / 是否被停止 → 结构化 `meta`，由界面渲染成小标签；
- **选项不写进正文**：`接着做 / 换个做法 / 让另一台先做` → 结构化 `options`，界面画按钮；
- **两个 agent 的往来**：群窗口里有一段「队友之间的往来」，回复自动挂 `replyTo`；
- **对话有终止条件**：同一主题 10 分钟内超过 `MAX_DIALOGUE_NOTES = 6` 条就停止自动应答，
  改为在群里请甲方定（继续讨论 / 只让一台做 / 先停下）。

## 3.3 身份标识（0.10.3）
- 统一为 `系统类型 · 设备名`，一处计算（`deviceLabel`），群发言/成员/看板/账本/手机页共用；
- 设备名取系统里用户看到的名字（Windows `COMPUTERNAME`、macOS `scutil --get ComputerName`、Linux `/etc/hostname`）；
- 同名设备自动补 IP（没有 IP 就补设备号短码）；
- 身份 id 的种子保持旧格式，改名不换身份（否则两台互相的信任名单会失效）。

## 3.4 谁是甲方、谁是队友、哪些是说给你听的（0.10.4）

用户 2026-11-25：「agent 需要直到对方身份、用户身份，哪些是说给它听的，哪些不是」。

- 群消息带 `to`（说给哪台；空 = 所有人）。甲方的回答填成提问那台。
- 提示词有「## 谁在说话」：甲方 / 你 / 队友三方身份 + 判据：
  - `to` 是本机或空 → 处理；
  - `to` 是别的设备 → **只参考**，不执行、不回答、不重跑；
  - 队友之间 → 参考结论，别重复它做过的事。
- 群消息行会标「说给本机 / 说给 macOS · xxx」；广播不带标注。
- 接收端三层判据（`to` → `assignee` → 提问者），不是给自己的只记录。

## 3.5 两个坑（0.10.4 修）

1. **只读执行把 `team_sync` 也收窄掉了** → agent 说「这次会话里没有可用的群消息工具」，
   跑完什么都发不出。沟通不是写操作，`team_sync` 现在在 `ALWAYS_ALLOWED` 里。
2. **回执靠会丢的 id** → 重载后 `groupConversationId` 为空、续跑后 `syncRequirementId` 丢失，
   于是跑完群里一句话没有。现在起跑时记 `groupRun`，回执只看这个标记。
3. 顺带：`normalizePeer` 以前没读 `repo`，对端永远显示「未绑定 GitHub 仓库」，
   项目门禁也因此退化 —— 现已保留。

## 4. 去掉的东西

- `classifyGroupIntent` 不再参与分流（模块保留，仅作离线分析用）；
- 群里的「无工具干答」支路（`answerGroupChat`）不再走主路径。

## 5. 代价（必须接受）
每条群消息都走一次完整 agent 轮次：**更慢、更耗 token**。
用户已明确接受（"我要的是聪明"）。

## 6. 验收标准

- [ ] 群里问「有没有同步功能」→ 群里出现**带依据**的结论（引用具体文件/字段），不是"看起来可以"；
- [ ] 群里说「让 macos 做」→ 只有 mac 执行，Windows 只记录并说一句；
- [ ] 需要授权 → 群里出现请求，回「授权」后继续、回「拒绝」后停下；
- [ ] 一轮结束 → 群里必有结果（成功或未完成），不需要去右侧对话框翻；
- [ ] 只有一条「团队任务」会话，不因每条消息新增；
- [ ] 关掉协作 → 该会话隐藏；重开 → 复用同一条。
