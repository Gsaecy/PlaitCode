# HWChat 局域网协作 · 功能需求规格

> 这是**功能需求**，不是排障记录。接手的人按这份实现或校正即可，不需要再问用户。
> 基线版本：`honor-world.hwchat@0.4.32`（2026-11-24）

---

## 1. 一句话定义

**两台电脑连在同一个 WiFi 下，各点一次按钮就配对成功；之后在「团队群」里说的话，两台电脑上的 AI 一起去完成，谁做了什么两台都看得见。**

---

## 2. 解决谁的什么问题

| 项 | 内容 |
|---|---|
| 用户 | 不懂编程的需求方，用中文说想法 |
| 场景 | 同一个 app 的 Windows 版和 macOS 版，两台电脑各负责一版 |
| 现状痛点 | 一台说「改了」、另一台什么都没收到；用户无法判断谁说的是真的 |
| 因此本功能的**硬要求** | 任何「已同步」「已完成」都必须有凭据；没有确认就如实说没有 |

**这是整个功能的第一原则，优先于其它一切。** 宁可显示「没连上」，也不许把「不知道」显示成「成功」。

---

## 3. 用户视角的完整流程（只允许这些步骤）

1. 两台电脑的 VS Code 各装一次 HWChat。
2. 两台各点一次状态栏的「连接另一台设备」。**顺序不限**：先点的那台等待，后点的那台连上去。
3. 状态栏显示已连接。
4. 打开「团队群」窗口，在里面说一句话。
   - 想换项目就**在群里说一句**（`用 deepseek-hwchat` / `切到 personal-workstation` / `换成 plaitcode`），不需要先去菜单里选；
   - 没有「先选项目再开群」这一步：开群不需要项目。
5. 两台电脑的 AI 一起开始做；双方在群里看得到彼此的发言、进度、结果。
6. （可选）手机扫码，在手机上看同一个群、下指令、批准授权。

### 步骤 3 的硬性要求

全程用户**不需要**：填 IP、填端口、填配对码、改任何设置、开任何开关、看文档。
如果某一步必须让用户做额外操作，视为**设计不合格**。

### 例外（允许存在，但不能是主路径）

同一路由器下 UDP 广播被拦（例如公司 WiFi 禁广播）时，可以提供一个「高级 → 手动填写对方 IP」入口作为兜底。用户只填 IP，**端口必须自动补齐**（只填 `192.168.0.3` 就应连到 `192.168.0.3:47821`，不能连 80 端口）。

## 4. 界面需求

### 4.1 状态栏（唯一主入口，常驻可见）

必须能区分这 5 种状态，**文案不得含糊**：

| 真实情况 | 状态栏文案 | 禁止写成 |
|---|---|---|
| 没连，也还没点 | `连接另一台设备` | — |
| 已点，正在等对方 | `等待另一台加入` | `1台`、`已连接` |
| 从机，已连上主机 | `已连主机 · 已对齐` | — |
| 主机，已有一台连进来 | `已连 1 台 · 已对齐` | — |
| 有分歧未对齐 | `已连 N 台 · M 处待对齐` | 只说「已对齐」 |

**关键约束**：台数**只统计连到的对方设备，不含本机**。
（历史 bug：把本机算进去，一台都没连上却显示「1台」，用户误以为成功。）

点击状态栏 = 打开同步详情。

### 4.2 团队群窗口

必须包含：

- **顶部状态条**：`已连接` / `已连主机` / `等待另一台加入` / `未连接`，配一句说明当前该做什么。
- **群发言流**：按时间顺序，显示发言人（设备名 + 平台）、内容、时间。
- **任务看板**：每条需求的状态（待做 / 进行中 / 已完成 / 未执行）。
- **输入框 + 发送按钮**：输入框下方说明「这条会发给频道里所有设备」。
- **可指派**：可以选「所有人」或指定某台设备执行。
- **停止执行**按钮。

**硬性要求**：
1. 用户点发送后，**本条发言必须立刻出现在群发言流里**（同一台设备，无需刷新、无需重开窗口）。
2. 对端收到后，**对端群发言流里也要出现同一条**。
3. 若服务未启动导致发不出去，必须当场提示，**不允许静默**。

### 4.3 设置页 →「协作」

只放**当前真的能用**的按钮。每加一个按钮前，先确认它的依赖可用；不可用的**直接删掉**，不要留灰按钮或「即将上线」。

当前应存在的按钮：

| 按钮 | 作用 | 依赖 |
|---|---|---|
| 连接另一台设备（主按钮） | 发起配对 | 无（纯局域网） |
| 打开团队群 | 打开群窗口 | 无 |
| 手机遥控（扫码） | 手机端二维码 | 无 |
| 打开对齐账本 | 打开 `docs/PLATFORM-ALIGNMENT.md` | 无 |
| 断开 | 停止协作 | 无 |

**明确不做**：任何依赖远程服务器的按钮（「开始协作 / GitHub 登录」）在服务器可用之前不得出现在界面上。

### 4.4 「同步核对」命令

命令面板可执行，一屏输出以下内容，并自动复制到剪贴板：

```
===== HWChat 同步核对 =====
时间：<本地时间>
本机：<设备名> · <本机局域网 IP>

[局域网]
状态：未启用 / 主机，正在等另一台加入 / 已加入 <对方地址>
监听端口：<实际端口>（发现端口 <配置端口>）
对端设备：<N> 台
  - <名字> · <平台> · <地址>

[判定]
- 局域网：可用，另一台能收到 / 不可用（还没连上另一台）
- 结论：现在发出去的内容 <有/没有> 设备会收到
```

用途：用户遇到「一边说改了、一边没有」时，两台各跑一次，对比即可裁决。**这条命令是信任的落点，不能省。**

### 4.5 对齐账本

在项目里维护 `docs/PLATFORM-ALIGNMENT.md`，记录每条需求在各平台的状态，随项目一起提交。人和 AI 都能读。

## 5. 行为规则（核心逻辑，不得简化）

### R1 只有「团队群」会广播

- 团队群里发的话 → 广播给频道内所有设备；
- **主对话里发的话 → 只给本机**，并且第一次发生时提示一次「这条只发给了本机，要两台一起做请在团队群说」；
- 从对端收到的消息 → **不再转发**（否则两台会无限互相转发）。

### R2 只有需求会触发执行

- `kind=requirement` 的消息 → 对端 agent 开跑；
- 群发言、进度、结果 → **只记录与展示，不触发对端执行**。

> 这条不能改。放开会让两个 AI 互相接龙，把额度烧光。

### R3 失败必须如实

- 没连上任何通道时发需求 → 返回失败，文案明确写「**没有同步到任何其它设备**」；
- 发送失败要单独计数，并在成功时清除上一次的错误（不能一次失败就永久显示断开）；
- 群消息发不出去 → 当场弹出提示，并说明怎么办。

### R4 同一份活不要两台都做

消息带指派对象时，只有被指派那台执行；本机不执行并提示「已指派给 X」。
理由：两个人各改一遍会互相覆盖，比没人做更难查。

### R5 配对要傻瓜式但有边界

- 第一次连接陌生设备，本机弹一次「允许吗」，点允许后记住，以后自动重连；
- 不允许多台设备未经确认就连进来；
- 只允许局域网内（同一网段）设备互连，不做公网暴露。

### R6 端口冲突自动降级

配置端口被占用时，**自动改用系统分配的端口**继续工作，对端靠广播包里携带的真实端口连过来，用户不应感知到任何异常。

### R7 不允许「自己加入自己」

本机广播会回环到自己。发现与配对时必须**跳过本机地址**，否则会显示「已加入主机 <自己的IP>」——界面说连上了，实际一台都没连。

### R8 两台都点按钮时自动收敛

两台同时点，会各自成为主机，谁也不连谁。必须自动决定谁让位：
- 按设备 id 比较，id 大的让位去加入对方，id 小的继续当主机；
- 只允许一边让位，不能两边同时让；
- 遇到**旧版本设备**（广播里没有设备 id 字段，且它不会让位）时，本机**无条件让位**。

### R9 自动恢复

上次连过，这次打开 VS Code 不用再点：上次是主机就继续待命，上次连了某台就重连那台；重连失败要退回「成为主机待命」，不能卡在一个永远失败的连接上。

### R10 项目在群里选，不做事前选择

- 开群 / 加入**不要求**选项目；当前项目默认是「当前正在编辑的文件所在文件夹」，不是 `workspaceFolders[0]`。
- 群里说「用 xxx / 切到 xxx / 换成 xxx（也认仓库名）」→ 立即切到该项目，并在群里回一句「已切到 xxx，项目 ID 是 …」；另一台本地有同一项目时自动跟着切。识别必须保守：明确动词（切 / 换 / 改成 / 改用）才算；含糊动词（用 / 做 / 打开 / 选）只有整句很短才算；一句话点两个项目不猜；只提到项目名不算。
- 项目身份是**仓库地址**（`projectRef.ts` 归一化），文件夹名只作展示。

## 6. 验收标准

以下每一条都必须实际发生，不接受「代码看起来对」：

- [ ] 两台无配置的机器，只点一次按钮即可连上
- [ ] 连上前后状态栏文案与 4.1 表格逐字一致，**不会出现「1台」这种含糊说法**
- [ ] 团队群发出的发言，**发送方与接收方群窗口都立刻出现**
- [ ] 团队群发出的需求，**两台 agent 都开始执行**
- [ ] 主对话发出的需求**不会广播**，并提示一次
- [ ] 没连上时发需求，提示「没有同步到任何其它设备」
- [ ] 同步核对显示 `局域网：可用` 且 `对端设备：1 台`
- [ ] 两台都点按钮时能自动收敛成「一台主机 + 一台从机」
- [ ] 端口被占用时仍能连上（自动换端口）
- [ ] 设置页里每个按钮都真的能用
- [ ] 群里说「用 xxx 项目」，那台立刻切过去，另一台本地有就自动跟着切；两台项目 ID 一致
- [ ] 群里问「现在在哪个项目」，回答里有真实项目名与仓库地址
- [ ] 一台加入后，**两台**都立刻显示「群聊中 · 2 台设备」（不需要谁先说话）
- [ ] 群里说一句「报数」，**两台 agent 各回一句**（各报自己的设备与项目）

## 7. 技术约束（不要违反）

| 约束 | 原因 |
|---|---|
| 不改 `SYNC_PROTOCOL_VERSION`（当前 `1`）、`PLAITCODE-SYNC-DISCOVER/1`、`PLAITCODE-SYNC-HUB/1` | 改了就和已安装的旧设备不兼容 |
| 扩展 ID 保持 `honor-world.hwchat` | 用户 239MB 历史数据在这个路径下 |
| 配置键用 `hwchat.*` 前缀 | 与扩展名一致 |
| 不引入新的网络依赖 | 局域网协作必须不依赖任何服务器 |
| 不改权限/审批相关逻辑 | 与协作无关，改动会波及安全边界 |
| 「已同步」类文案必须有凭据 | 见第 2 节第一原则 |

### 消息流转（必须理解这条链）

```
团队群输入框
  → GroupPanel callbacks.send
  → chatPanel.sendGroupMessage()
  → chatPanel.send(origin: 'group')
      ├─ lanSync.postGroup(...)        → 写进群记录 + 广播
      └─ lanSync.shareRequirement(...) → 广播 kind=requirement
  → 对端 applyMessage()
  → 对端 runRequirement()              → 对端 agent 真的开跑
```

## 9. 已经踩过的坑（不要重复）

| # | 坑 | 表现 | 正确做法 |
|---|---|---|---|
| 1 | 没连通道时消息被静默丢弃 | 一边说「已同步」，另一边什么都没有 | 必须返回失败并明确告知 |
| 2 | 端口号含本机 | 一台没连也显示「1台」 | 台数只算对方设备 |
| 3 | 自己加入自己 | 「已加入主机」的地址就是本机 IP | 发现与配对都跳过本机地址 |
| 4 | 两台都成主机 | 谁也不连谁，各自待命 | 按 id 让位，只一边让 |
| 5 | 广播周期漏带设备 id | 两台新版互相误判成旧版，**双方同时让位**，反而都连不上 | 广播必须带设备 id |
| 6 | 首播延迟 15 秒 | 同时点按要干等 | 立即可播一次 |
| 7 | `setLanSync()` 从未被调用 | 群窗口空白，群消息不进群、不广播，只有本机主对话在跑 | 启动协作时必须注入服务 |
| 8 | 状态栏写「中继重连中」 | 实际连着的是已下线的服务器，用户以为迟早会送达 | 直接写「连不上」 |
| 9 | 手动填 IP 不带端口 | 连到 80 端口必然失败 | 自动补端口 |
| 10 | 群消息触发对端执行 | 两个 AI 互相接龙烧额度 | 只有 requirement 触发执行 |

## 10. 验证方式

```bash
npx tsc --noEmit                    # 必须 0 错误
node esbuild.mjs                    # 必须成功
node --test out/test/*.test.js      # 全量
```

**基线：1536 条 / 1495 通过 / 39 失败。**
那 39 条是环境性失败（Windows 路径、端口占用、进程组信号），与协作无关。
判定标准：**新增失败为 0**，失败清单与改动前逐条一致。

真机验证必须两台设备实际连一次，不接受只跑单测。

## 12. 当前进度与风险

**已实现并自测通过**：R1～R9 的代码路径、同步核对命令、状态栏四态、端口降级、让位规则（含单元测试）。

**尚未真机验证**（这是当前最大风险）：
> 两台设备（macOS + Windows）实际连接后，团队群发言是否双向可达、两台 agent 是否都执行。

接手者请**第一件事就做真机验证**（两台都装同一版本 → 各点一次 → 群里发一句），不要基于「代码看起来对」下结论。若不通，用第 4.4 节的同步核对输出定位，再改代码。
